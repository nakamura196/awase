# VRM 読み上げペイン

## 2026-10-25

### 経緯

非公開のアプリ nakamura196/vrm-script-reader-next（VRM のアバターが台本を読む）を、awase のペインとして移した。
元のアプリは、あらかじめ作った台本 JSON（音声ファイルと口形素 viseme つき）を再生していた。

### 決めたこと

- **音声はブラウザの音声合成（Web Speech API）にした。** 事前に音声を作らなくても、発話（sp・said）のある TEI なら何でも読める。
  代わりに口は「開閉」だけで、口形素には合わせない（話している間の振動と、`onboundary` での開きの強調）
- **同梱するのは boy.vrm（約 20MB）だけ。** girl.vrm（27MB）は載せない。`vrm=<URL>` で別のモデルを指せる
- **panes を書かないときは出さない（オプトイン）。** 20MB を読むため。`panes` に `vrm` を明示したときだけ出す。
  そのため `togglePane` は、書いていない状態から vrm を出すと、ほかのペインも全部書き出す
- three と @pixiv/three-vrm（3.5.5 に固定）は、ペインが出たときに動的に読み込む
- 読み上げの声は、TEI の xml:lang（text、ルートの順）、無ければ画面の言語で選ぶ

### 確かめたこと・確かめていないこと

- 純粋な部分（声の選び方、言語の決め方、発話の送り方、panes の出し入れ）は vitest で確かめた
- 画面の出し入れは Playwright で確かめた。ヘッドレスでは WebGL が使えない場合があり、アバターの描画そのものは目で確かめていない部分がある
- 実際の VR 機器では試していない
- 声は OS・ブラウザで違う。日本語の声が無い環境では既定の声になる

## 2026-10-25（続き）台本 JSON（json=）への対応

### 移したもの

元のアプリが再生していた台本 JSON を、同じペインで再生できるようにした（`json=<URL>`、`filter=all|head-only|upper-body|no-fingers`）。
JSON を付けないときの動きは、上の記述のまま（本文の発話をブラウザの音声合成で読む）。

- 台詞と本文の発話の対応づけ（`src/lib/vrm/script.ts` の `alignDialogues`）
- 口形素（Azure の viseme ID 0〜21）から VRM の aa/ih/ou/ee/oh への対応表。元の `useVisemePlayer` の表のまま。
  音声があるときは再生位置、音声合成のときは開始からの経過 × 速さで時刻を決め、なめらかにつないで口に反映する
- 感情から表情への対応（happy/angry/sad/relaxed/surprised）と、強さによる重み付け。台詞の頭と終わりでなめらかに出し入れする。
  **元のアプリのコードには感情名の対応表が無かった**（表情は動きの blendShape track に入れる設計で、このサンプルには無い）。
  そのため joy→happy、anger・hatred・disgust→angry、fear→sad、confusion→surprised、thinking→relaxed などの対応は、こちらで決めたもの
- 体の動き（クォータニオンのキーフレームを slerp で補間）と、`filter` によるボーンの絞り込み。
  元のアプリはキーフレームの値をボーンの向きとして直接入れていたので、腕を下ろした姿勢では腕が T ポーズに戻ってしまう。
  ここでは「腕を下ろした基準の姿勢 × 動きの差」にしている（サンプルは時刻 0 が単位クォータニオンなので差として読める）。
  確かめたのは見た目だけで、他のモデル・他の台本での向きの正しさは確かめていない
- 待機の揺れ（呼吸・体の揺れ）。JSON の有無にかかわらず常に入る
- 話者ごとの声: 台本の Azure の声名（ja-JP-NanamiNeural）の核（Nanami）を含む声があればそれ。無ければ言語に合う声を、出てくる順に割り当てる。
  同じ声を使う話者には声の高さを変えて聞き分けられるようにした（TEI だけのときも同じ）
- 視点の操作（OrbitControls。顔を中心に、回る範囲と寄れる範囲を絞った）、「視点を戻す」ボタン、「自動で次へ」のチェック

### 台詞と本文の対応づけ

台本の台詞 ID（act一-002）は TEI の xml:id と対応しないので、本文で突き合わせる。
ルビ記法（`{{親|ふり}}`）・空白・句読点・記号を落とした文字列で、文字 2-gram の Dice 係数と「短いほうがどれだけ長いほうに含まれるか」の大きいほうを近さとする（0.5 未満は同じ発話とみなさない）。
順序を保った 1 対 1 の対応のうち、近さの合計（話者名が一致すれば +0.1）が最大のものを動的計画法で選ぶ。
本文は第一幕だけでなく全幕の発話（135 件）を含むが、順序を保つので、台本が第一幕だけでも合う。

サンプル（芥川『三つの宝』第一幕、台詞 37 件）で、36 件が本文の発話に対応した。
残りの 1 件は、最初の台詞（ナレーターのト書き。本文では `<stage>` で、発話ではない）で、これは想定どおり。
対応しなかった台詞も再生はされ、本文のハイライトだけが付かない。
確かめていないこと: 他の作品、台本と本文の版が違う場合、同じ台詞が繰り返される場面での取り違え。

### 移さなかったもの

- girl.vrm、モデルの選択画面、VRM ファイルのアップロード: 容量（27MB）と、`vrm=` で別のモデルを指せることで足りるため
- 登場人物ごとに別の VRM を割り当てる機能: 台本にモデルの指定が無く、今回の範囲を超えるため
- 元のアプリの試験用のページ（test 系）
- 元のアプリの「感情の自動切り替え」の設定: 表情は台詞ごとに常に入る

### 見つからなかったもの

- 音声ファイル（wav）はどこにも無かった。台本の `audio.path` は読みに行って、読み込めなければブラウザの音声合成に切り替える
  （サンプルは必ず切り替わる）。音声合成が使えない・始まらないときも、目安の時間（音声の長さ、無ければ文字数×0.17 秒）だけ進めて次へ行く
- TEI から台本 JSON を作った変換の道具（感情・動きの生成）も見つからなかった。サンプルの JSON は本人が作ったものをそのまま同梱している
